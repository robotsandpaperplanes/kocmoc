# Telegram-бот сертификатов KOCMOC

Бот на Python 3.9+ и aiogram 3. Покупка пока работает в тестовом режиме:
кнопка `Оплатить N ₽` не списывает деньги, а сразу создаёт сертификат в
SQLite.

## Что реализовано

- `/start` с приветствием «Я верю, что многие из вас...»;
- нижнее меню `🕰️ Который час?`, `⚓️ Плыть`, `🎁 Сертификат`,
  `📦 Мои сертификаты`, `👽 Купить юз @kocmoc`;
- отдельный сценарий покупки юзернейма с ответами «Да» и «Нет» и
  возвратом в главное меню;
- текущее время в UTC+0 и 24-часовом формате;
- четыре результата команды «Плыть»: «Вы плывёте ✅» — 96%,
  «Вы летите 🫵 🤣» — 1%, «Вы испугались воды 😰» — 2,5% и
  «На вас упал огнетушитель 🧯» — 0,5%;
- inline-команда `⚓️ Плыть`, доступная через `@имя_бота` в любом
  Telegram-чате без добавления бота в группу;
- покупка сертификата номиналом 5 000, 10 000, 30 000 или 50 000 ₽;
- необязательный комментарий;
- отображение комментария длиной максимум 1000 символов: 999 символов и `…`;
- случайный уникальный ID сертификата в формате `xxxx-xxxx`;
- список и карточки сертификатов пользователя;
- `/myid` для получения Telegram ID;
- `/admin` для разрешённых администраторов;
- поиск по ID, подтверждение и атомарное погашение;
- защита от повторного погашения;
- сохранение времени, Telegram ID и username администратора;
- автоматическая миграция базы из архивной MVP/V2.
- идемпотентная выдача: повторная обработка одного платёжного события не
  создаёт второй сертификат;
- проверяемые онлайн-копии SQLite с автоматическим удалением старых копий;
- уведомления администраторам о необработанных ошибках и сбоях резервного
  копирования;
- автоматическая проверка тестов в GitHub Actions.

## Настройка

Создайте файл `.env` из примера:

```bash
cp .env.example .env
```

Заполните:

```env
BOT_TOKEN=токен_из_BotFather
DATABASE_PATH=./data/bot.sqlite3
ADMIN_TELEGRAM_IDS=123456789
BACKUP_DIR=./data/backups
BACKUP_INTERVAL_HOURS=24
BACKUP_KEEP_COUNT=14
NOTIFY_ADMINS_ON_ERROR=true
```

Для нескольких администраторов перечислите Telegram ID через запятую или
пробел. В Bothost рекомендуется пробел, если интерфейс обрезает значение после
запятой:

```env
ADMIN_TELEGRAM_IDS=123456789,987654321
# или
ADMIN_TELEGRAM_IDS=123456789 987654321
```

Чтобы узнать ID, запустите бота и отправьте `/myid`. После изменения `.env`
перезапустите процесс. Команда `/admin` не показывает административные данные
пользователям, которых нет в `ADMIN_TELEGRAM_IDS`.

Файл `.env` исключён из Git. Не добавляйте в репозиторий токен бота.

`BACKUP_INTERVAL_HOURS=24` создаёт резервную копию при запуске и затем каждые
24 часа. `BACKUP_KEEP_COUNT=14` оставляет последние 14 проверенных копий.
Значение `BACKUP_INTERVAL_HOURS=0` отключает автоматическое копирование.
В production `DATABASE_PATH` и `BACKUP_DIR` должны находиться на постоянном
диске хостинга. Например:

```env
DATABASE_PATH=/app/data/bot.sqlite3
BACKUP_DIR=/app/data/backups
```

## Запуск в GitHub Codespaces

Из корня репозитория:

```bash
cd telegram_certificate_bot
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
```

Откройте `.env`, вставьте `BOT_TOKEN`, затем запустите:

```bash
python -m app.main
```

После запуска откройте бота в Telegram и отправьте:

```text
/start
```

## Inline-команда «Плыть»

Один раз включите inline-режим:

1. Откройте `@BotFather`.
2. Отправьте `/setinline`.
3. Выберите бота.
4. Укажите подсказку, например `Выберите команду`.

После этого в любом Telegram-чате введите `@имя_бота`, поставьте пробел и
выберите `⚓️ Плыть`. Результат отправится в текущий чат. Под ним останется
кнопка `⚓️ Плыть`: другой участник сможет нажать её, выбрать команду и
отправить свой независимый результат.

Если виртуальное окружение и `.env` уже существуют:

```bash
cd telegram_certificate_bot
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m app.main
```

Остановка на компьютере: `Ctrl+C`. В мобильном Codespaces можно удалить
активный терминал кнопкой корзины и создать новый.

## Запуск через Docker

```bash
cd telegram_certificate_bot
cp .env.example .env
docker compose up --build
```

SQLite хранится в `telegram_certificate_bot/data/bot.sqlite3` и подключается к
контейнеру как volume.

## Тесты

```bash
cd telegram_certificate_bot
source .venv/bin/activate
python -m pytest -q
```

Тестами покрыты генерация ID, усечение комментария, обе вероятностные ветки,
создание сертификата, коллизия ID, повторное платёжное событие, резервное
копирование и запрет повторного погашения. Те же тесты автоматически
запускаются для pull request и изменений основной ветки.

## Данные сертификата

Для каждого сертификата сохраняются:

- внутренний UUID и публичный ID `xxxx-xxxx`;
- Telegram ID и username покупателя;
- номинал и полный исходный комментарий;
- статус и время создания;
- время погашения;
- Telegram ID и username первого администратора, который его погасил.

Для совместимости сохраняются старые технические поля заказов и QR-токенов.
Существующая база обновляется при запуске без удаления данных.

## Реальная оплата

Интеграция с ЮMoney сейчас не включена. При её добавлении создание сертификата
нужно вызывать только после подтверждения успешного платежа через
`Database.issue_paid_certificate`. В метод передаются:

- стабильный `invoice_payload` заказа;
- ID платежа Telegram, если используется Telegram Payments;
- ID платежа провайдера;
- проверенные Telegram ID покупателя, номинал и комментарий.

Повторная доставка события с теми же платёжными идентификаторами вернёт уже
созданный сертификат. Если идентификаторы относятся к другому пользователю,
номиналу или заказу, выдача будет отклонена. Пользовательский список, карточки
и админское погашение при подключении оплаты менять не потребуется.

## Проверка перед выпуском

На тестовом боте выполните один полный сценарий:

1. Купить сертификат с комментарием и проверить его в «Моих сертификатах».
2. Открыть `/admin`, найти ID и подтвердить погашение.
3. Повторно попробовать погасить тот же ID и проверить предупреждение.
4. Перезапустить процесс и убедиться, что сертификат и его статус сохранились.
5. Проверить появление файла в `BACKUP_DIR`.
6. Убедиться, что `.env` не отображается в `git status`.

Для настоящей оплаты дополнительно повторно доставьте одно и то же тестовое
событие провайдера и убедитесь, что в базе появился ровно один сертификат.
