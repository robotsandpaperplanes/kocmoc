# Telegram-бот сертификатов — тестовый MVP

Бот работает на Python и aiogram 3. Реальная оплата временно отключена: кнопка **«Оплатить»** сразу выпускает случайный UUID-сертификат без списания денег. Это позволяет полностью проверить пользовательский и админский сценарии с телефона.

Требуется Python 3.11 или новее.

## Пользовательский сценарий

1. `/start` показывает нижнее меню: `menu_item_1`, `menu_item_2`, `Сертификат`.
2. После выбора «Сертификат» нижняя клавиатура заменяется кнопками номиналов.
3. После выбора номинала она заменяется действиями для комментария.
4. После подтверждения появляется нижняя кнопка «Оплатить».
5. «Оплатить» в тестовом режиме создаёт:
   - случайный UUID сертификата;
   - секретный QR-токен;
   - изображение сертификата с номиналом, ID, комментарием и QR.
6. QR открывает этот же Telegram-бот по deep link.

На каждом шаге бот отправляет новую `ReplyKeyboardMarkup`, поэтому кнопки предыдущего шага не должны оставаться в нижней панели.

## Админка в Telegram

Доступ определяется по Telegram ID из `ADMIN_TELEGRAM_IDS`.

Администратор может:

- открыть раздел «Админка» из главного меню;
- найти сертификат по полному UUID или короткому коду `CERT-…`;
- посмотреть последние активные сертификаты;
- сканировать QR сертификата и сразу открыть карточку в боте;
- погасить активный сертификат после отдельного подтверждения;
- увидеть дату и Telegram ID сотрудника, который его погасил.

Повторное погашение не меняет запись: операция выполняется атомарно.

## Настройка `.env`

```env
BOT_TOKEN=токен_из_BotFather
DATABASE_PATH=./data/bot.sqlite3
ADMIN_TELEGRAM_IDS=123456789
```

Чтобы узнать свой Telegram ID:

1. запустите бот с пустым `ADMIN_TELEGRAM_IDS`;
2. отправьте боту `/myid`;
3. остановите бот;
4. вставьте полученное число в `.env`;
5. запустите бот снова.

Для нескольких сотрудников укажите ID через запятую:

```env
ADMIN_TELEGRAM_IDS=123456789,987654321
```

Старые строки `PAYMENT_PROVIDER_TOKEN`, `CERTIFICATE_BASE_URL` и `ADMIN_REDEEM_SECRET` можно оставить в существующем `.env`: новая версия их игнорирует.

## Запуск в Codespaces

```bash
cd telegram_certificate_bot
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m app.main
```

Если окружение и `.env` уже созданы:

```bash
source .venv/bin/activate
pip install -r requirements.txt
python -m app.main
```

Остановить бот: `Ctrl+C`.

## Проверка тестами

```bash
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты проверяют выпуск UUID-сертификата, создание PNG, миграцию базы первой
версии, запрет повторного и конкурентного погашения, список администраторов и
состав нижних клавиатур.

## SQLite

Хранятся:

- тестовый заказ;
- UUID сертификата;
- короткий код;
- секретный QR-токен;
- номинал и комментарий;
- статус `active`/`redeemed`;
- время создания и погашения;
- Telegram ID сотрудника, погасившего сертификат.

Существующая база обновляется автоматически: колонка `redeemed_by` добавляется при запуске.

## Возврат реальной оплаты

Позже обработчик кнопки «Оплатить» можно заменить на Telegram Payments + ЮKassa. Выпуск сертификата должен происходить только после подтверждённого `successful_payment`; админский интерфейс и QR-сценарий при этом сохраняются.
